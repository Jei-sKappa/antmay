---
description: A document enters the project layer only when the user accepted it at the end of a discussion, and the spec is the only step that drafts it, so a thread that lands nothing is the ordinary case.
---

At the end of a discussion the agent proposes the records, glossary terms and agents-file changes the thread would land, few or none being a valid proposal, and only what the user accepts reaches the log as `document` entries, from which `spec` drafts the delta documents and from nothing else. The gate is a person saying yes to each document, because a written test an agent applies alone does not bound how many documents a project accumulates.

## Rejected alternatives

- `spec` applying the decision test alone — a prose test applied by an agent does not bound volume.
- `spec` queueing the candidates a discussion missed as pending decisions — it reinstates the pressure to surface every candidate.
- `close-thread` drafting what the log settled but no delta holds — it would have to infer which log entries lack a delta.
- `discussion` drafting the delta at acceptance — a later point in the same discussion can supersede it.
