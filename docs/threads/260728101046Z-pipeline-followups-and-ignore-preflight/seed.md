# Close out the stage-selection follow-ups and refuse runs whose operational folders are not ignored

The thread at `docs/threads/260727135009Z-choose-compose-run-stages/` replaced the CLI's executor-bundled pipeline with user-authored pipeline documents: a trusted nine-stage catalog, a bounded artifact-state engine with per-stage prerequisites and promised transitions, syntax-directed document references, `--from` suffix selection, a redesigned checkpoint, a full ordered run preflight, and runtime contract enforcement with four deterministic resume recoveries. Every one of its plan tasks shipped, but its `implementation-report.md` closes with a list of remaining concerns and follow-ups that were deliberately left outside that plan's scope. This thread exists to work that list down. Its first job is judgment: some entries are plain defects to fix, some are deliberate trade-offs that should be documented rather than changed, and each is decided on its merits rather than executed as a checklist.

The list, as that report leaves it:

**Published documentation and vocabulary.** `cli/README.md` groups `review-spec` with the stages that "may touch only `spec.md`", but that stage's `allowedChanges` is empty — it permits no tracked change at all, so the published prose understates the policy. `docs/glossary.md`'s **stage** definition omits the artifact prerequisite and promised transition the catalog now owns, and it — together with `docs/recipes/standard.md` — reads as though the CLI ships the `standard` pipeline rather than publishing a document the user saves; the root `AGENTS.md` names the glossary the repository's naming authority, and `docs/` was outside the previous plan's scope. A `stage-prerequisite-unmet` pause keeps the ordinary clean-worktree resume rule, so a human must commit the restored artifact before resume is accepted, which the pause's own `Next:` line does not say.

**Dead and duplicated code.** `DocumentReference.form` is consumed nowhere outside its own test and should be removed, with `DocumentReference.raw` weighed at the same time. `gitCursor.headAtStageEntry` is write-only and should be retired or documented as diagnostic-only. `queueReasonsFor` in `runner.ts` re-implements `classify.ts`'s private `queueReasons` including its precedence; `describeContractSide` is duplicated between `runner.ts` and `resume.ts`; four copies of `isPlainObject` remain; and the harness membership list exists as an array in `config/execution.ts` and as a `Set` in `state/checkpoint.ts`. In `config/execution.ts`, an `as HarnessId` cast sits inside the very check that narrows it, and the adjacent diagnostic's harness list should derive from `HARNESS_IDS`.

**Verification gaps.** The demo's `07-runtime-prerequisite` timing pair is documented but not asserted, because a `.mjs` scenario cannot import the TypeScript constant its `afterMs` must stay inside. The unverifiable-postcondition branch ships untested — it is unreachable end to end, since preflight rejects its only producible cause. The checkpoint validator requires each stage `id` to name a catalog stage but checks no other part of the descriptor against that entry, which is what keeps the runner's pipeline-agnosticism provable with synthetic fixtures. The documentation check for a "user-visible reason" is structural rather than semantic, so it cannot detect a long but internally worded reason. And the manual real-harness smoke checklist has never been run: it needs real Codex and Claude Code credentials plus installed skills, so it is human-run by nature.

**Preflight coverage for operational workspaces.** The run preflight that same thread rebuilt is where https://github.com/Jei-sKappa/antmay/issues/18 belongs, so that issue is folded in here. Antmay skills create three thread-local operational workspaces — `.pending-decisions/`, `.pending-reviews/`, and `.implementation-runs/`. When a repository does not ignore those paths, the initial preflight still passes while the directories are absent; a later stage then creates untracked operational files and is blocked by that stage's Git boundary even though its intended work was correct. `antmay afk run` should verify, before allocating run state or invoking a harness, that every required operational workspace path for the selected thread is effectively ignored by Git, and refuse — naming the missing ignore coverage together with an actionable correction — when any is not. This turns a predictable late-stage boundary failure into an immediate setup error.

The intended outcome is a CLI whose published documentation and glossary describe what the code actually does, whose retired fields and duplicated helpers are gone, whose accepted verification gaps are either closed or recorded as deliberate, and whose run preflight refuses a thread whose operational workspaces are not ignored by Git.
