# Implementation report

Source: plan.md

## Outcome

All 16 plan tasks completed and committed (one commit per task). The strict, non-interactive `antmay afk` CLI is implemented end-to-end as a self-contained Node/TypeScript package under `cli/`: package scaffold and CLI grammar; config/state root resolution and settings validation; the recipe model with the built-in six-stage `standard` recipe and per-harness prompt rendering; `--thread` resolution with genesis validation; the `schemaVersion: 1` checkpoint model with atomic persistence, run IDs, and attempt logs; the `current-checkout` workspace strategy, sha256 workspace lock, and pending-queue scanner; the Sandcastle 0.12.0 harness adapter and `--version` executable probe; terminal-outcome parsing and result classification; the git boundary engine; the generic recipe-agnostic stage runner; the terminal display; the `run`, `resume`, and `list` commands; and SIGINT/SIGTERM/SIGHUP signal handling. The spec's required whole-package gate (`npm --prefix cli run check`) passes.

No task was blocked, partial, or found already satisfied.

## Changes

- **New package `cli/`** — private, ESM, strict TypeScript, `tsup`-built shebang entry exposed as the `antmay` bin; scripts `build`/`typecheck`/`test`/`check`; Node ≥ 22 engine + early runtime guard; `@ai-hero/sandcastle` pinned to exactly `0.12.0`; package-local lockfile; `.gitignore` excluding `node_modules/` and `dist/`. The repository root gained no `package.json` or workspace config.
- **CLI surface** — strict `util.parseArgs` grammar (`afk run <recipe> --thread <path> [--dangerously-skip-permissions]`, `afk resume <run-id>`, `afk list`, help/version at all three levels) with nearest-usage errors and exit-code constants; a guarded dynamic bootstrap (`main.ts` → `program.ts`) so help/version/grammar errors never load config/state/Git/harness subsystems; each command's heavy dependencies are dynamically imported only when that command is selected.
- **Configuration** — pure config/state root resolvers with documented precedence, empty-as-unset, absolute-path enforcement, and no expansion; a manual strict `settings.json` validator aggregating all errors with property paths and recipe-agnostic stage-key validation; `cli/README.md` with a macOS-only notice, a copyable settings example, a stale-workspace-lock section, and a manual smoke checklist.
- **Recipe/harness core** — serializable recipe/stage descriptors; the built-in `standard` recipe matching the spec's stage table (targets, three-part Git policies, exact commit-subject templates, `advance`/`rerun` queue resolution); target/selector resolution; profile resolution (seed → defaults → stage override, plain replacement); byte-exact prompt rendering; the Sandcastle adapter behind a provider-neutral `HarnessInvoker` boundary with exact option mapping, permission policies, and structural error normalization; the aggregating `--version` probe.
- **Durable state** — the checkpoint type family and a manual validator enforcing field types plus cross-field invariants; atomic checkpoint writes (exclusive temp file, fsync, rename, best-effort dir fsync) behind an injectable `FsOps` seam; run-ID generation and exclusive `0700` run directories; exclusively created `0600` attempt logs with the full Antmay header; the sha256 workspace lock with owner-token-guarded release; the pending-queue scanner.
- **Orchestration** — terminal-outcome parser and pure classification-precedence function; the git boundary engine (NUL-delimited status set, declarative policy evaluation, finalization staging only validated paths and committing exact subjects, never pushing/amending/rebasing/bypassing hooks or creating empty commits); the generic stage runner (attempt lifecycle, queue gates, finalize-before-queue-pause, checkpoint transitions, per-attempt heartbeat); signal handling (graceful first-signal interruption, hard second-signal exit); the `run` command (ordered preflight, lock-guarded allocation with under-lock queue recheck, initial `ready` checkpoint), the `resume` command (state-root-only revalidation, per-kind resume behavior including harness-free boundary finalization and abandoned-`executing` recovery), and the read-only `list` command.
- **Tests** — deterministic Vitest suites across all modules using an injected harness interface, disposable Git-repo fixtures, fake harness processes, and fake version executables — no real model calls; 337 tests across 28 files.

## Deviations and judgment calls

- **Checkpoint/lock JSON field names and shapes** (spec degree of freedom 3) were chosen concretely and kept stable across downstream tasks — the `RunCheckpoint` key set, `workspace` shape (`path === execution.cwd`), `AttemptRecord.terminalResult` shape, the `.state.json.<hex>.tmp` temp-file naming, and the attempt-log header line order.
- **Commit-subject placeholder token.** The spec prose writes the boundary commit placeholder as `<full-thread-folder>`, while the recipe descriptors store the literal token `<thread-folder>`; boundary finalization substitutes the full canonical thread-folder name (with UTC prefix) for the token the descriptors actually carry, so subjects render as e.g. `docs(260723121015Z-afk-workflow-executor): spec`.
- **`manual-recovery` origin on abandoned-`executing` recovery.** The plan asked to mark the recovered abandoned attempt `interrupted` with `diagnostics.origin: "manual-recovery"`, but `AttemptRecord` has no `diagnostics` field (that field lives on `WaitingInfo`, and recovery transitions to a `ready` cursor with `waiting: null`, not an interrupted waiting pause). The attempt's `result` is set to `interrupted` and the manual-recovery origin is recorded in the attempt's `failure.message`; this is a faithful satisfaction of the spec transition text and AC-14.2 given the committed schema.
- **`program.ts` touched outside a task's stated file list** during signal handling: removing the bare injected `signal` from `RunDeps` (as the plan directed) made the old wiring uncompilable, so `program.ts` was updated to rely on the new `createAbortController`/`installSignals` seam defaults — a necessary compile-time consequence, not a behavior change.
- **Minimal test-only seams** were added where deterministic tests required them: an injectable `open` seam on the lock, an optional `generateId` seam on `RunDeps` (production never sets it) for the under-lock queue-race and ID-collision tests, and the injectable `FsOps` seam on checkpoint persistence. All are production-inert.

## Remaining concerns

- **DONE boundary committed + simultaneous queue-scan failure classifies as `gate-error`.** In the classification precedence, a parsed DONE whose boundary is valid and already committed but whose post-attempt queue scan simultaneously fails falls to `gate-error` (the attempt records `waiting`), and a `gate-error` resume starts a new attempt at the same stage — re-running a stage whose boundary was already committed. The DR57 carve-out that preserves the boundary kind is scoped to boundaries "still requiring finalization" (violation/commit-error), so this valid+committed race is not covered. This is a rare I/O-race edge owned by the classification precedence and the spec's resume rules, not a defect in the runner (which faithfully finalizes-before-classifies). It was not patched during this run because resolving it is a spec/classifier decision, not a plan-mechanics fix.
- **Idle-timeout error match is keyed to the literal tag `AgentIdleTimeoutError`.** The adapter detects Sandcastle's idle timeout structurally (no Sandcastle type may escape the adapter); a future Sandcastle rename of that error would silently reclassify idle timeouts as `provider-error`. Inert while the dependency is pinned to `0.12.0`.

## Follow-ups

- Adjudicate the DONE-boundary-committed + queue-scan-failure edge above against the spec: decide whether the DR57 boundary-kind-preservation carve-out (or the resume behavior for `gate-error` over an already-committed boundary) should be extended so an already-committed DONE stage is not re-run, then adjust `classifyAttempt` and/or the resume dispatch accordingly. This is a task-scoped-review gap for the verify stage, which checks the implementation against the spec's acceptance criteria.
- A few minor, non-blocking code-quality notes surfaced during review and were intentionally left as-is: first-token dispatch expressed as `for` loops in the CLI parser; a small duplicated `useColor`/`paint` pair between `printRunSummary` and `createTerminalDisplay`; `list.ts` defining its own small ANSI helper rather than a shared one; an unused `HarnessId` type import in `resume.ts`; and defensive redundancy in the profile-push guard.
