# Implementation report

Plan: none

## Outcome

Completed. `open-thread` no longer rephrases a ticket: a linked ticket's body is
reproduced into the seed under a `## Ticket` heading, and the thread is created
without a confirming pass. `open-ticket` now authors its body as the genesis
narrative a thread inherits, and keeps its own confirmation because that write
leaves the repository. The run executed no plan; the thread's `seed.md` and the
eleven settled points in its `log.md` are what it answered to, as no `spec.md`
was authored for this thread.

## Changes

- `suite/shared/references/instructions/create-thread.md` — the seed section
  gains a "The genesis narrative" subsection: a linked ticket's body goes under a
  `## Ticket` heading reproduced exactly, context the invocation added sits
  beneath that block, a ticket-only invocation produces a seed with no prose
  besides the block, and a thread opened without a ticket keeps the composed
  narrative. The metadata list moved under its own subsection. The mirrored copy
  under `open-thread` was regenerated by `scripts/sync-shared-references.mjs`.
- `suite/skills/capture-discussion/open-thread/SKILL.md` — the genesis-narrative
  field carries a ticket's body through unchanged and keeps invocation context
  separate; "Create the thread" drops the confirmation pass and states why a
  repository-local write does not need one; "Report" names the path, slug, title,
  and metadata, and forbids printing the narrative.
- `suite/skills/capture-discussion/open-thread/references/supplied-ticket.md` —
  the ticket is read to be reproduced rather than for context, with its lists,
  fences, and line breaks intact, and a pasted body is treated identically; the
  duplicate-thread check now informs through the report instead of asking whether
  to continue.
- `suite/skills/capture-discussion/open-ticket/SKILL.md` — the body is stated to
  *be* the genesis narrative rather than prose a thread could reuse, in both the
  opening rationale and the body field; the confirmation pass gains the reason it
  survives where a repository-local write would drop it.
- `suite/authoring/interaction-posture.md` — `open-thread` moves from
  dialogue-driven to one-shot deliverable, and a new paragraph fixes when a
  one-shot deliverable confirms at all, keyed to where its write lands.
- `README.md` — the terminal-outcome paragraph follows that reclassification, and
  the `open-thread` and `open-ticket` entries state the coupling between them.

## Deviations

- The duplicate-thread prompt in `supplied-ticket.md` was removed, not kept —
  departs from the settled point, which named the confirmation pass alone — because
  it was a second interactive gate on a skill that no longer pauses, and the same
  paragraph already claimed the check "never blocks the operation". It now informs
  through the report.
- `open-thread`'s composed **title** and **slug** still rephrase the ticket's
  subject — departs from nothing settled, and was listed as an inference at the
  discussion's close with the note that it is the last place the agent rewrites
  the ticket's words. Left as the discussion left it.

## Remaining concerns

- The rule that a repository-local write skips confirmation while a tracker write
  keeps it now lives in `suite/authoring/interaction-posture.md` and in the two
  skill bodies, but in no ADR — the thread deliberately drafted none. A later
  thread could even out the asymmetry without meeting the reasoning.
- A ticket not filed by `open-ticket` can still produce a seed that does not stand
  on its own. That was accepted during the discussion and is hand-edited when it
  happens; nothing guards it.

## Follow-ups

- `docs/glossary.md` still defines **seed** as carrying "a self-contained genesis
  narrative". The thread's `glossary.md` amends **genesis narrative** only, so the
  **seed** row will merge back inconsistent unless that delta gains a row for it.
  This run does not write either file.
- `cli/README.md` describes `open-thread` as a stage that "interviews you for the
  thread's founding intent and then creates the thread folder", which this change
  makes untrue. The stage stays `Unsupported`, so the table's answer does not
  move, only its wording. Drift recorded and left alone under the CLI hold; the
  realignment pass picks it up.
