### Task 2: Create the `instructions/` shared-reference kind

**Objective:** Give the suite a home for self-contained procedures — `suite/shared/references/instructions/` — populated with the six instructions the spec names, declared in the manifest for the skills that read them, and synced.

**Input / context:** `spec.md` § "Shared reference kinds → Instructions" (the six-row table and the register rules) and AC-2.1, AC-2.3, AC-2.5. Settled decisions: `decisions.md DR7` (the instruction kind and its criterion), `DR1` (primitive content becomes instruction files; the precondition-and-refuse blocks are dropped), `DR5` (append mechanics live once in `append-log-line.md`), `DR3` (the report is written once, from the run's outcome material, with no reference to an earlier report), `DR13` (the thread layout `create-thread.md` implements). Material to draw from: the four primitive bodies `suite/skills/primitives/*/SKILL.md` (still on disk in this task; task 3 deletes them), the `## Appending` text `log-line.md` carried before task 1, and the terminal-outcome text repeated across the completion-oriented bodies (`spec`, `plan-brief`, `plan-strict`, `check-plan`, `implement*`, `review-*`, `roadmap`, `close-thread`). Task 1's `formats/thread.md` fixes the layout `create-thread.md` writes. The manifest still uses the pre-rename skill paths (`skills/finish-navigate/close-thread`, `skills/primitives/*`) — declare against the paths that exist now; task 3 renames the key.

Register for every instruction file: imperative, addressed to whoever performs the act, naming no skill (`/skill-name` tokens, the words "primitive" and "caller", and "the calling skill" do not appear), covering one act with a defined result, carrying no precondition-and-refuse block. Headings inside a file are free.

**Steps:**

1. Create `suite/shared/references/instructions/create-thread.md` (NEW) from `allocate-thread`'s body: capture the current UTC time; compose the folder path `.wip/threads/yyyy/mm/dd-hhmm-slug/` (four-digit year folder, two-digit month folder, leaf `dd-hhmm-slug` with the supplied kebab-case slug; when a folder with that leaf already exists, the slug must differ — pick a more specific slug rather than a suffix); create the folder; write `seed.md` in the order title heading, genesis narrative verbatim, applicable conditional metadata lines (`External:`, the pair `Roadmap:` + `Entry:` with the index path in the form `.wip/roadmaps/<yymmddhhmm>-<slug>.md`, `Supersedes:`), absent metadata simply absent; create `log.md` with a single shell write carrying only the header line `# Thread log`; create nothing else; report the created path as the thread's identifier relative to `.wip/threads/`. Drop the `## Precondition and refusal` content and the "direct the user to /open-thread" sentence.
2. Create `suite/shared/references/instructions/append-log-line.md` (NEW): append one entry as a single-line shell append of the form

   ```sh
   printf '%s\n' '- (type) gist with the reason folded in' >> <thread root>/log.md
   ```

   never open `log.md` with a file-editing tool; never re-read the file after the session's opening read; one writer per session — a session that fans out to subagents appends only from the orchestrator; the line's type is one of the seven the log-line format fixes and the framing that produced the point (options, recommendation, deliberation) is never copied into the line.
3. Create `suite/shared/references/instructions/emit-pending-decisions.md` (NEW) from the `emit-pending-decisions` primitive: allocate one bundle file per run under the thread's `.pending-decisions/` (created on demand), never appending to or reusing an existing bundle; name it `<UTC>-<suffix>-<slug>.md` (UTC timestamp, short unique suffix, kebab-case slug — example `260712142301Z-a3f9-retry-ownership.md`); write it per the pending-decision-bundle format — the `Producer:` line reads `/<your own skill name>` — the performer fills in its own name at write time, and the instruction itself names no skill; target, originating request, and one point per genuine open human decision, each with what is blocked, why the answer could not be derived, the evidence weighed, and a free-text suggestion only when an immediate fix is visible; never write an empty bundle, never disguise a defect, observation, or report material as a decision; one bundle per coherent target — split only when points have meaningfully different targets. Drop the precondition-and-refuse block.
4. Create `suite/shared/references/instructions/emit-pending-review.md` (NEW) from the `emit-pending-review` primitive: when there are zero actionable findings write no file and return the concise pass in chat; otherwise allocate one uniquely named bundle under the thread's `.pending-reviews/` (same naming scheme, example `260712142301Z-a3f9-spec-handoff.md`); write the routing header (`# Pending review: <title>`, `Reviewer: /<your own name>`, `Target:`, `Created:`, `Findings: <count>`), an optional `## Context` with the overall assessment, then `## Findings` with one `### FND<N>: <short title>` section per finding carrying `Severity:` (`blocker` | `issue` | `nit`), `Category:`, `Finding:`, `Evidence:`, `Impact:`, and `Suggested action:` only when supportable; number sequentially from `FND1`; order blockers, issues, nits; the bundle carries no disposition, status, or retry instruction and never writes `.pending-decisions/`. Pin the header and finding block shapes in fenced Markdown, since this is the only place the bundle's shape lives. Drop the precondition-and-refuse block.
5. Create `suite/shared/references/instructions/write-implementation-report.md` (NEW) from the `update-implementation-report` primitive: write `report.md` inside this run's implementation folder once, at the run's terminal outcome, per the implementation-report format; the `Plan:` line names the plan folder executed or reads `Plan: none`; fold the outcome material from the run's progress file — what completed, partially completed, blocked, or was found already satisfied; the resulting changes; the checks actually run with their results, failures, and justified skips; deviations each naming what was built, the spec section or ADR stem it departs from, and why; remaining concerns; follow-ups; state partial, blocked, and no-op outcomes plainly; never claim a check that was not run; keep out per-task status blocks, transcripts, dispatch counts, fix-loop detail, and any path under `.runs/`. No merge semantics and no mention of an existing report.
6. Create `suite/shared/references/instructions/emit-terminal-outcome.md` (NEW): end the run's final chat message with exactly one line `Outcome: <TOKEN> — <one-line reason or pointer>`; the vocabulary is closed to `DONE` (the requested job completed, non-blocking concerns included), `BLOCKED` (substantive execution started and stopped — queued pending decisions or an unfixable operational defect), `REFUSED` (preflight prevented the run from starting); the line is the last line of the message, it is added to rather than replacing any summary the skill's own instructions call for, and the reason part is the confirmation text the skill's own instructions give (for example `Outcome: DONE — Spec written: spec.md`, `Outcome: BLOCKED — pending decisions at <bundle path>`, `Outcome: REFUSED — <reason and how to re-invoke>`).
7. Declare the instructions in `suite/shared/manifest.yaml`, adding `instructions/<file>` entries under the existing keys:
   - `instructions/create-thread.md` → `skills/capture-discussion/open-thread`
   - `instructions/append-log-line.md` → `skills/capture-discussion/discussion`, `skills/capture-discussion/resolve-pending-decisions`, `skills/spec/spec`
   - `instructions/emit-pending-decisions.md` → `skills/capture-discussion/resolve-pending-decisions`, `skills/spec/spec`, `skills/plan/plan-brief`, `skills/plan/plan-strict`, `skills/plan/check-plan`, `skills/implement/implement`, `skills/implement/implement-plan`, `skills/implement/implement-plan-with-subagents`, `skills/roadmap/roadmap`, `skills/finish-navigate/close-thread`
   - `instructions/emit-pending-review.md` → `skills/review/review-spec`, `skills/review/review-implementation`, `skills/review/review-code`
   - `instructions/write-implementation-report.md` → the three `skills/implement/*`
   - `instructions/emit-terminal-outcome.md` → `skills/spec/spec`, the three `skills/plan/*`, the three `skills/implement/*`, the three `skills/review/*`, `skills/roadmap/roadmap`, `skills/finish-navigate/close-thread`
   Also add `formats/pending-decision-bundle.md` to every key that now declares `instructions/emit-pending-decisions.md` and does not already declare it (the instruction points at the format).
8. Update the header comment of `suite/shared/manifest.yaml` only if it names formats as the only kind; it should describe sources as files relative to `shared/references/` (it already does — leave it if so).
9. Run `cd suite && node scripts/sync-shared-references.mjs && cd ..`. The script copies arbitrary relative paths, so `instructions/` needs no script change; if it fails, fix the manifest, not the script.

**Files modified:** `suite/shared/references/instructions/create-thread.md` (NEW), `suite/shared/references/instructions/append-log-line.md` (NEW), `suite/shared/references/instructions/emit-pending-decisions.md` (NEW), `suite/shared/references/instructions/emit-pending-review.md` (NEW), `suite/shared/references/instructions/write-implementation-report.md` (NEW), `suite/shared/references/instructions/emit-terminal-outcome.md` (NEW), `suite/shared/manifest.yaml`, and the generated copies `suite/skills/<group>/<skill>/references/instructions/*.md` and `references/formats/pending-decision-bundle.md` for each declaring skill (written by the script).

**Verification:**

```sh
ls suite/shared/references/instructions/ | sort
# AC-2.1: six files, no skill names, no precondition/refuse blocks, no "primitive"/"caller"
grep -nE '/(allocate-thread|emit-pending-decisions|emit-pending-review|update-implementation-report|open-thread|discussion|spec|implement|close-thread|roadmap|review-[a-z]+|plan-[a-z]+|check-plan)\b' suite/shared/references/instructions/*.md
grep -niE 'precondition|refus|primitive|\bcaller' suite/shared/references/instructions/*.md
grep -n 'docs/threads\|docs/roadmaps' suite/shared/references/instructions/*.md
grep -n '\.wip/threads/yyyy/mm/dd-hhmm-slug' suite/shared/references/instructions/create-thread.md
grep -c 'instructions/' suite/shared/manifest.yaml     # >= 32
(cd suite && node scripts/sync-shared-references.mjs) >/dev/null
awk '/^[^ #]/{k=$1; sub(/:$/,"",k)} /^  - /{print k"\t"$2}' suite/shared/manifest.yaml | while IFS=$'\t' read k src; do cmp -s "suite/shared/references/$src" "suite/$k/references/$src" || echo "OUT OF SYNC $k $src"; done   # nothing
find suite/skills -path '*/references/instructions/*.md' | wc -l
```

The first `ls` prints exactly the six names. The two `grep -n`/`grep -niE` scans of the instruction files print nothing except the `Reviewer: /<…>` and `Producer: /<…>` placeholder lines, which name no skill. The `docs/threads` grep prints nothing. The `create-thread.md` grep prints at least one line. The manifest count is at least 32. The `find` count equals the number of manifest instruction entries.

- `suite/shared/references/instructions/` holds exactly `create-thread.md`, `append-log-line.md`, `emit-pending-decisions.md`, `emit-pending-review.md`, `write-implementation-report.md`, `emit-terminal-outcome.md`.
- Each file is imperative, covers one act, names no skill, and carries no precondition-and-refuse block; `create-thread.md` implements the `.wip/threads/yyyy/mm/dd-hhmm-slug/` layout and writes only `seed.md` and a header-only `log.md`; `write-implementation-report.md` describes one write from the run's outcome material with no merge semantics.
- `suite/shared/manifest.yaml` declares each instruction for exactly the skills listed in step 7, and the synced copies exist under each declaring skill's `references/instructions/`.
- The sync script runs clean and a second run changes nothing.

**Produces:** the six instruction files at `suite/shared/references/instructions/<name>.md` and their synced copies at `references/instructions/<name>.md` inside each declaring skill — the paths the body tasks 4–7 point at; the manifest entries task 3 re-keys for `close-thread`.
