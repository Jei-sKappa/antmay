Completed. ## Deviations

- Removed "with this thread's identifier as the thread in hand" from `close-thread`'s procedure step 3 — departs from the spec's `## Scope and non-scope`, which lists only the instruction, its copies and the README — because the instruction no longer takes a thread in hand, so the clause would point at a step that no longer exists. Hit handling in that step is unchanged.
- One ERE, `[0-9]{4}/[0-9]{2}/[0-9]{2}-[0-9]{4}-[a-z0-9]`, run with `git grep -E` — the spec's `## Degrees of freedom` leaves the regex to the implementer. It requires the slug to start with a lowercase letter or digit, per the thread format's kebab-case slug.

## Remaining concerns

- The expression matches any identifier-shaped string, so a date-plus-time path unrelated to threads (for example `2026/09/23-0737-backup` in a log path) would be a hit. That fits the spec's choice to inspect plausible references rather than miss them, and every hit is still judged by a reader.
