# Own the suite's install, update, and remove lifecycle across harnesses

Antmay ships its skills through the generic `npx skills add Jei-sKappa/antmay` flow, which copies each skill flat into a harness's skill directory and writes no manifest and no provenance. Nothing on disk records which installed skill came from which repository, so retiring a skill from the suite cannot remove it from a machine that already has it. The failure is observable: a maintainer's own machine carries sixteen skills the suite retired — `allocate-thread`, `append-roadmap-feedback`, `archive-thread`, `emit-pending-decisions`, `emit-pending-review`, `finish`, `materialize-roadmap-threads`, `merge-artifacts`, `propose`, the four `reconcile-*` skills, `review-roadmap`, `update-implementation-report`, and `whats-next` — while four current skills (`check-plan`, `close-thread`, `consult-adrs`, `consult-glossary`) were never installed. Author metadata cannot disambiguate them, because the same author publishes a second skill repository whose skills sit in the same directory.

Antmay should own this experience rather than inherit it. The intended outcome is a single script, invocable from a command the README publishes and a user pastes (`curl … | sh` or equivalent), that runs interactively for a human and has a non-interactive mode for agents and CI. It reads local state and resolves which of three situations it is in: a first install, an update from a known version, or an installed copy whose contents no longer match the version recorded for it. It installs to `~/.agents/` and links or copies into each supported harness — Claude Code, Codex, OpenCode, Cursor, and Pi. macOS is the supported platform; Linux follows only where it is identical.

Making removals mechanical requires a real changelog and, alongside it, a machine-readable per-release manifest naming the exact skill set of that release, so the script derives what to add and what to remove by diffing manifests rather than by parsing prose. Local state should record a content hash per installed skill so the script can distinguish a stale copy from one the user deliberately edited, and decline to overwrite the latter without an explicit force. A pasted `curl` command carries no integrity check, so a versioned URL and a published checksum should exist as the careful path.

Two things are deliberately outside this work. The `cli/` module is on stand-by and behind the suite; it is not the home for this and is not to be touched. And the broader project-setup concerns in issue #11 — seeding a consuming repository's `AGENTS.md` with an explanation of the thread method, and verifying that a project's companion setup is coherent — are related but separate; this thread is the install, update, and remove lifecycle itself. The skill directories for OpenCode, Cursor, and Pi are not yet verified against their documentation and must be confirmed before the layout is fixed.
