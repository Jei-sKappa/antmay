# Implementation report

Plan: plans/2609280932/

## Outcome

Completed: all eleven plan tasks ran and were committed. In the suite, the project layer is now decision records, the glossary, the agents files and the roadmap indexes. A record, glossary term or agents-file change enters it only through a `document` log line that a discussion's closing offer writes for a candidate the user accepted. `spec` drafts project-layer delta documents from those lines alone, and `review-spec` checks record shape and that every entry has its delta. `close-thread` lands agents files under a 1,000-word ratchet and a passage check. The descriptive kinds and `consult-descriptions` are gone from the suite, its registrations and the maintainer and user-facing documents.

This repository's own project layer changes only at close: the thread's `delta/` carries the two new PDRs, the glossary edit, the root and suite `AGENTS.md` edits, and the deletes of `docs/product/method.md`, `docs/architecture/suite.md` and PDR 2609230721-thread-design-document-is-the-spec. No delta target was edited here, so the acceptance rows that depend on those files are met at close. Their delta documents were checked and are ready to land.

## Deviations

- `spec`'s opening paragraph reads "draft the spec body and one delta document for each `document` entry still in force", and `## Procedure` step 3 reads "draft the delta documents per `## Draft the delta documents`". This departs from the plan's wording for the opening paragraph. The old sentences described sorting every settled point to its home, which `## Draft the delta documents` no longer does. The "or one operation within one" nuance stays in that section.
- `close-thread`'s agents-file input now says the root `AGENTS.md` is still read as standing guidance, while the budget and passage checks read no agents file whole. This departs from the plan's wording, which read "No agents file is read whole" and contradicted the neighbouring input that reads the root `AGENTS.md`.

## Remaining concerns

- The kept present-tense rule in `formats/decision-record.md` still says "no version in name, stem or body", though records no longer have a `name` field.
- The two landed records in `docs/adr/` and `docs/pdr/` still carry `name:` frontmatter. The catalog ignores it, and records already landed keep their shape.
- `discussion` step 8 checks a term against "the admission test" in the glossary format, but that format never uses the phrase, so its rule is unnamed.
- If the user stops a discussion before the inference list, `discussion` goes straight to Finish. Held terms and directly requested documents are then never offered or logged.
- Step 8's "state that the discussion is finished" repeats Finish item 1.
- `close-thread`'s changed-path command uses `<base>^`, which fails when the seed was added in the repository's root commit. `git diff -M` against the working tree also does not report an unstaged rename as a rename, though both paths still enter the list.
- `roadmap`'s planned-behavior sentence says "one statement" twice, copying the roadmap-index format's wording.
- `README.md`'s opening still calls the project layer "the fixed set of paths". That matches the thread's glossary delta, so if "fixed" is ever dropped, the glossary row and the README should change together.
