# mattpocock/skills — documentation research

Clone: `.library/sources/mattpocock_skills/` (shallow, single commit, version 1.2.3 per `package.json`). All paths below are relative to that root.

## Summary

- **Only two standing doc types are prescribed for user projects: a glossary (`CONTEXT.md`) and ADRs (`docs/adr/`).** Both are created lazily, and consumers are told to "proceed silently" when they are missing: "Don't flag their absence; don't suggest creating them upfront" (`skills/engineering/setup-matt-pocock-skills/domain.md:11`). There is no product or architecture description, no roadmap, and no runbook tier. Specs, tickets, handoffs, reports and research are all treated as disposable.
- **The ADR bar is stricter than Antmay's decision test, and the ADR is much shorter.** All three conditions must hold: hard to reverse, surprising without context, and a real trade-off (`skills/engineering/domain-modeling/ADR-FORMAT.md:29-37`). The agent only *offers* an ADR, "sparingly" (`domain-modeling/SKILL.md:66-74`). The template is a title plus 1–3 sentences. "Considered Options" is optional (`ADR-FORMAT.md:9-23`). The published docs page counts "few or no ADRs" as the skill working (`docs/engineering/domain-modeling.md:79`, `docs/engineering/grill-with-docs.md:71`).
- **Prose gates did not stop bloat in the field.** The docs page for `domain-modeling` reports `CONTEXT.md` files of "500 lines. 1,000. 3,000" and calls this "the most-reported problem with the skill": models treat "write to `CONTEXT.md`" as "permission to persist every answer you give". It also admits the guidance "is not yet strong enough to prevent the growth" (`docs/engineering/domain-modeling.md:44,54-55`). This is direct evidence for Antmay complaints 1 and 2.
- **The strongest idea for Antmay's leaning direction is the "cache" rule** in `skills/productivity/writing-for-agents/SKILL.md:79`. A document that restates the environment (scripts, config, directory layout, `--help`) "is a cache", and earns its place "only when the lookup is expensive". The rule is: "Cache what the agent cannot find by looking … Leave the one-file, one-command lookups to the environment, where they cannot go stale." This nearly restates the leaning direction.
- **`AGENTS.md`/`CLAUDE.md` is treated as a pointer file.** The in-progress `retro` skill says these files "should be used incredibly sparingly, usually only for **navigation pointers** to other files" (`skills/in-progress/retro/SKILL.md:41`). Mechanical rules should become lint, hook or CI checks "full stop" (`retro/SKILL.md:19`). The setup skill writes a `## Agent skills` block into the user's `CLAUDE.md` with one line per topic plus "See `docs/agents/<x>.md`" (`setup-matt-pocock-skills/SKILL.md:84-100`).
- **Nothing mechanical keeps docs in sync with the source of truth,** in either layer. CI only runs changesets versioning (`.github/workflows/release.yml`). The only drift check is a plugin-version comparison (`scripts/sync-plugin-version.mjs`), and its `--check` mode is not wired into CI. Every sync rule in `CLAUDE.md` is prose. The invariants I checked by hand do hold at this commit. But stale references exist: `CONTEXT.md:19`, `.agents/adr/0001…:8`, `.agents/adr/0002…:9`, and the orphaned `skills/productivity/teach/GLOSSARY-FORMAT.md`.
- **Drift is handled by deleting duplicates and by writing for durability.** Duplicated install commands "went stale" and were "deleted rather than corrected" (`.agents/writing-docs.md:19`, `.agents/install-block.md:53`). Specs, tickets and agent briefs are told not to cite file paths or line numbers because "they go stale" (`skills/engineering/to-spec/SKILL.md:55`, `skills/engineering/triage/AGENT-BRIEF.md:9-17`).
- **Work records are thrown away on purpose.** Nothing feeds back into standing docs through a formal landing step. The spec "goes stale the first time implementation teaches you something. Treat it as throwaway once the work ships. The artifacts meant to outlive it are your `CONTEXT.md` and your ADRs" (`docs/engineering/to-spec.md:54`). Keeping planning material in the repo "tends to lead to accidental persistence" (`docs/engineering/wayfinder.md:78`).
- **Agent-facing text is short; human-facing text is long.** Promoted `SKILL.md` files have a median of 559 words. The human docs pages about them have a median of 1,579 words, about 3x more, and are written to a template that is itself 2,045 words (`.agents/writing-docs.md`).

## 2. Creation

**What triggers a new doc, and who writes it.** An agent writes it, during a conversation-driven skill. There are no generators.

**Glossary.**
- A term is written "the moment" it is resolved: "Don't batch these up" (`domain-modeling/SKILL.md:60-62`).
- The file is created only "when the first term is resolved" (`domain-modeling/SKILL.md:40`).
- Inclusion rule: "Only include terms specific to this project's context. General programming concepts … don't belong even if the project uses them extensively" (`CONTEXT-FORMAT.md:29`).
- The file is defined narrowly: "a glossary and nothing else … totally devoid of implementation details" (`domain-modeling/SKILL.md:64`).

**ADRs.** Three gates, all required (`ADR-FORMAT.md:31-37`):

> If a decision is easy to reverse, skip it: you'll just reverse it. If it's not surprising, nobody will wonder why. If there was no real alternative, there's nothing to record beyond "we did the obvious thing."

- The friction is a human consent step. The agent *offers* and the user accepts (`domain-modeling/SKILL.md:66`).
- `improve-codebase-architecture` narrows this further. Offer an ADR on a rejected candidate "only when the reason would actually be needed by a future explorer to avoid re-suggesting the same thing; skip ephemeral reasons … and self-evident ones" (`skills/engineering/improve-codebase-architecture/SKILL.md:70`).
- `ADR-FORMAT.md:39-47` lists what qualifies, for example "Constraints not visible in the code" and "Deliberate deviations from the obvious path".

**Out-of-scope records.**
- Written only when an *enhancement* is rejected as `wontfix`.
- Explicitly not written for "already implemented", because that "would poison the dedup checks" (`skills/engineering/triage/OUT-OF-SCOPE.md:84-88`).
- One file per *concept*, not per issue (`OUT-OF-SCOPE.md:17`).

**Setup docs.** Explore first, draft, let the user edit, then write (`setup-matt-pocock-skills/SKILL.md:15,63-70`). Sections are skipped when exploration has already settled them (`:36`).

**Human docs pages in this repo.**
- The trigger is "When you add, rename, or change the behaviour of a skill in `engineering/` or `productivity/`" (`CLAUDE.md:17`).
- `writing-docs.md:48-54` makes "Common questions" evidence-driven: "An observed question always beats an invented one". The count "stays honest to the evidence … Padding a thin skill out to match a rich one is how the section fills with questions nobody has". Optional sections are omitted, not filled.

**Contrast with Antmay.** There is no routing table that sorts every settled point. Most decisions stay unrecorded by design: "Everything else you decided | The conversation, and nowhere else" (`docs/engineering/grill-with-docs.md:33-39`). The page admits the cost: "the bulk of what you agreed exists only in the context window", and "Where did all my other decisions go?" is "the most substantive open complaint" (`grill-with-docs.md:39,54-55`).

- Model-invoked descriptions run 85–434 characters.
- The promoted set totals 29,493 words, including reference files.
- Line counts are misleading here: paragraphs are single long lines (`CLAUDE.md` is 25 lines but 489 words).

**Prescribed output lengths:**
- ADR: 1–3 sentences; "An ADR can be a single paragraph" (`ADR-FORMAT.md:12-15`).
- Glossary definition: "One or two sentences max. Define what it IS, not what it does" (`CONTEXT-FORMAT.md:28`).
- Handoff: no duplication; "Reference them by path or URL instead" (`skills/productivity/handoff/SKILL.md:12`).
- Teach mission: "If `MISSION.md` runs past a screen, it has stopped being a compass" (`teach/MISSION-FORMAT.md:31`).

**Density and audience:**
- Skills are dense and imperative, use bold "leading words", and have almost no narrative. `wait-what` is deliberately three lines: "Skills that fight verbosity fail by growing" (`docs/productivity/wait-what.md:5`).
- The `to-spec` template is the exception. It asks for "A LONG, numbered list of user stories … extremely extensive" (`to-spec/SKILL.md:33-41`). Its docs page concedes the spec is "complete, dense, reference-heavy" and that reading it whole is "a real complaint" (`docs/engineering/to-spec.md:51`).
- Audience can be read from the files. `.agents/` and `SKILL.md` are agent-facing: imperative, pointer-rich, no H1 rules. `docs/` pages are human-facing. `writing-docs.md:5` says their job is to relieve the human's "cognitive load". They use absolute links for publication (`:9`), and they are narrative, quoting user reports.

## 4. Sync with source of truth

**Mechanisms in code or CI:**
- `.github/workflows/release.yml`: on push to `main`, runs `changesets/action` (`npm run version`, which is `changeset version && node scripts/sync-plugin-version.mjs`). It opens a version PR. It does not validate content.
- `scripts/sync-plugin-version.mjs` copies `package.json` version into `.claude-plugin/plugin.json`. Its `--check` mode (`package.json` `check-plugin-version`) exits 1 on mismatch, but no workflow calls it.
- `claude plugin validate . --strict` is a manual instruction (`CLAUDE.md:11`).
- There are no tests, no lint, and no pre-commit hook in the repo. The no-em-dash rule (`CLAUDE.md:25`) is unenforced. `CHANGELOG.md` still contains 68 em-dashes even though that rule names `CHANGELOG.md`. Inference: these are older generated entries.

**Prose "same-change" rules (repo layer):**
- Every promoted skill must appear in `README.md` and `plugin.json`, and have a docs page (`CLAUDE.md:9,17`).
- The `ask-matt` router must be re-synced on any skill change, because "a stale one it still routes to, is a router that lies" (`CLAUDE.md:21`).
- `SKILL.md` and `openai.yaml` invocation flags must stay paired (`.agents/invocation.md:10`).
- I checked each of these by script at this commit, and all hold. The 25 promoted skills match 25 docs pages, 25 `plugin.json` entries, 25 README links and 25 `ask-matt` mentions, and every invocation flag is paired.

**Drift that got through anyway:**
- `CONTEXT.md:19` cites `ready-for-afk`. The canonical role is `ready-for-agent` (`triage/SKILL.md:35`). It also cites `docs/agents/triage-labels.md`, which does not exist in this repo.
- `.agents/adr/0001…:8` names `diagnose`, which was renamed to `diagnosing-bugs` (`CHANGELOG.md:250-253`).
- `.agents/adr/0002…:9` lists a `personal/` bucket, removed per `CHANGELOG.md:141`.
- `skills/productivity/teach/GLOSSARY-FORMAT.md` is linked from nowhere in `teach/SKILL.md`. The docs page documents the orphan instead of fixing it (`docs/productivity/teach.md:38`, issue #559).
- `CHANGELOG.md:217` says skills "never name a path" for the tracker doc and resolve it through the `CLAUDE.md` block. Yet `code-review/SKILL.md:13,29` hardcodes `docs/agents/issue-tracker.md`.
- The changelog records past drift: stale "PRDs" wording in seed templates "propagated into every repo they were written into" (`CHANGELOG.md:152`); a dead docs link (`:153`); stale `openai.yaml` display names (`:24`).

**User-project layer:**
- The only sync mechanism is conversational. `domain-modeling`'s "Cross-reference with code" step surfaces contradictions when the user states how something works (`domain-modeling/SKILL.md:56-58`). Consumers "flag ADR conflicts" rather than silently overriding (`setup-matt-pocock-skills/domain.md:47-51`).
- Seeded `docs/agents/*.md` go stale against newer skill versions (`docs/engineering/setup-matt-pocock-skills.md:59`). A verify mode was rejected: "run `/setup-matt-pocock-skills` and tell it to verify" (`.out-of-scope/setup-skill-verify-mode.md`).

**Expiry and deletion:**
- A retired skill is deleted, not kept in `deprecated/` (`skills/deprecated/README.md:3`).
- Reconsidered out-of-scope files are deleted (`OUT-OF-SCOPE.md:99-105`).
- Teach glossary and resources: "Update in place; do not leave stale entries", "Prune ruthlessly" (`GLOSSARY-FORMAT.md:35`, `RESOURCES-FORMAT.md:31`).
- ADRs are superseded via optional `Status` frontmatter. The repo's own ADR-0002 was instead amended in place with an "Update, 2026-08-05" section (`.agents/adr/0002…:32-41`).
- "`CONTEXT.md` gets shorter as often as it gets longer" is listed as a success signal (`docs/engineering/domain-modeling.md:82`). No skill step performs that pruning.

## 5. Agent-facing files

**`CLAUDE.md`** (489 words). It holds only invariants and procedures that no code enforces:
- bucket semantics and the promoted-set rule;
- the manifest validate command;
- the docs-page and router re-sync triggers;
- the invocation pairing;
- the local link script;
- the em-dash rule.

It leaves out any inventory of what the skills do (that is in `README.md` and the bucket READMEs), any tech stack, and `CONTEXT.md`. Deeper material is reached by pointers, some of them conditional: "When you add, rename, or change the behaviour of a skill … follow `.agents/writing-docs.md`" (`:17`), and "Why a Claude plugin … lives in `.agents/adr/0002…`" (`:11`).

**`CONTEXT.md`** (264 words). Four domain terms with `_Avoid_` synonyms, relationships, and "Flagged ambiguities" (resolved naming disputes). It is small because the format forbids implementation detail and general concepts (`CONTEXT-FORMAT.md:27-30`). Inference: this repo's domain is also small.

**Theory of pointers** (`skills/productivity/writing-for-agents/SKILL.md`):
- A "context pointer" is any always-loaded reference that encodes when to reach material (`:10-18`). Every word "costs on every turn".
- "Context load" and "cognitive load" are the two budgets (`:20-27`).
- Disclose what "only some branches reach" (`:39`).
- Sprawl and "sediment" are failure modes: "stale layers that settle because adding feels safe and removing feels risky" (`:43,80`).
- The no-op test is applied sentence by sentence (`:81`).
- The human docs page applies this to `CLAUDE.md` directly: "Anything that applies in one context out of ten is paying context load the nine other times" (`docs/productivity/writing-for-agents.md:49-50`).

**Progressive disclosure in the skills:**
- Sibling files are pointed at by branch: `prototype/SKILL.md:14-15` points to `LOGIC.md` or `UI.md`, and `writing-for-agents/SKILL.md:8` says "When the document you're writing is a skill, read `SKILL-MECHANICS.md`".
- Cross-skill sharing goes through Skill-tool calls, never `../` links (`.agents/invocation.md:16`).
- Soft-dependency skills mention the glossary and ADRs "in vague prose only" to stay "token-light" (`.agents/adr/0001…:8-10`).
- **Navigation guide as a lazy pointer:** `setup-ts-deep-modules` writes a short `README.md` next to the packages. It adds one conditional line to `CLAUDE.md`: "see [src/packages/README.md] before adding or importing one". The rule itself is enforced by a dependency-cruiser check the skill must see fail then pass (`skills/in-progress/setup-ts-deep-modules/SKILL.md:78-95`).

## 6. Hard-to-learn-from-code knowledge

- **Rationale.** ADRs, gated to the "why on earth did they do it this way?" case (`ADR-FORMAT.md:35`). Examples in `ADR-FORMAT.md:41-47` are all things code cannot show: compliance constraints, partner-API latency contracts, non-obvious rejected alternatives.
- **Domain language.** `CONTEXT.md` with `_Avoid_` lists. This is a cheap record of rejected synonyms. `codebase-design/SKILL.md:105-109` does the same for architecture vocabulary under "Rejected framings".
- **Rejected requests.** `.out-of-scope/` gives institutional memory and dedup (`OUT-OF-SCOPE.md:3-6`). The reason must be "durable", not "we're too busy right now" (`:68`).
- **Evidence.** Prototypes are kept as "primary sources" on unmerged branches and pointed at from the issue (`prototype/SKILL.md:26`, `docs/engineering/prototype.md:26-35`). A debugging session's winning hypothesis goes "in the commit / PR message, so the next debugger learns" (`diagnosing-bugs/SKILL.md:138`).
- **Procedures.** Procedures are turned into executables: `wizard` generates a bash script, "commit it and link it from the README so the next person runs the script instead of asking an AI" (`wizard/SKILL.md:44`).
- **Navigation.** `retro` has a "Navigation" finding category: "Would a **navigation pointer** make it easier? _Use when_ the session took a long time to find a piece of information" (`retro/SKILL.md:17`). This makes the navigation doc evidence-triggered rather than speculative.
- **Invariants.** There is no dedicated home. Mechanical invariants are pushed to checks (`retro/SKILL.md:19`). Judgement-call standards go to `CODING_STANDARDS.md`, "read during review, not implementation" (`retro/SKILL.md:42`, `code-review/SKILL.md:34-41`).

## 7. Work records

**Repo layer:**
- One changeset per change (`.changeset/*.md`, 22–217 words, stating rationale) is rolled into `CHANGELOG.md` by CI.
- Otherwise the records are GitHub issues and PRs, cited by number (for example `.out-of-scope/*.md` "Prior requests").
- The changelog feeds back into standing docs: it is one of three sources mined for docs-page "Common questions" (`.agents/writing-docs.md:50-52`).

**User layer**, where Antmay's thread is the analogue:
- Spec: an issue labelled `ready-for-agent`. Tickets: one per slice with blocking edges. Locally: `.scratch/<feature>/spec.md` and `issues/NN-slug.md` (`setup-matt-pocock-skills/issue-tracker-local.md:7-11`).
- Wayfinder map: "an **index**, not a store … a decision lives in exactly one place, its ticket, so the map never restates it, only gists it and links" (`wayfinder/SKILL.md:23`).
- Nothing lands anywhere at close. The spec is discarded after shipping, and anything durable "belongs" in `CONTEXT.md` or ADRs (`docs/engineering/to-spec.md:54`). No step enforces that move.
- Research: the community position is quoted as "ADRs yes. Everything else archive or delete after done. It otherwise becomes cruft … and can poison future repo reads" (`docs/engineering/research.md:41`).
- Handoffs and architecture reports go to the OS temp dir "so nothing lands in the repo" (`handoff/SKILL.md:8`, `improve-codebase-architecture/SKILL.md:39`).

## 8. Ideas to borrow and anti-patterns

**Ideas to borrow:**

1. **The "cache" test as the admission rule** (`writing-for-agents/SKILL.md:79`, `CHANGELOG.md:92`).
   - Addresses complaints 2 and 3 directly: restating a cheap lookup is both bloat and a drift liability.
   - Strongly supports the leaning direction. It also refines it: admit a doc when the lookup is *expensive*, which covers both "hard to tell" and "hard to find".
2. **A "hard to reverse" gate on decisions**, and "offer, don't write" (`ADR-FORMAT.md:29-37`, `domain-modeling/SKILL.md:66-74`).
   - Addresses complaint 1. Antmay's decision test has no reversibility clause. Adding one would drop the "easy to reverse, you'll just reverse it" class.
   - Making the rejected-alternatives section optional, and allowing 1–3-sentence records, addresses complaint 2.
3. **`CLAUDE.md` as a pointer file**, with one line per topic plus "See X", and conditional wording (`setup-matt-pocock-skills/SKILL.md:84-100`, `retro/SKILL.md:41`, `CLAUDE.md:17`).
   - Addresses complaint 2 and matches the leaning direction almost exactly.
4. **Navigation docs created only on observed friction** (`retro/SKILL.md:17`), co-located with the code they govern and paired with a check that enforces the rule (`setup-ts-deep-modules/SKILL.md:89-95`).
   - Addresses complaints 1 and 3.
   - Supports "hard to find" as a criterion, with an evidence trigger instead of a speculative one.
5. **"Mechanical rule → deterministic check, full stop; prose only for judgement calls"** (`retro/SKILL.md:19`, `.changeset/retro-deterministic-checks.md`).
   - Addresses complaint 3 by moving enforceable content out of docs altogether.
6. **Consumers stay silent on missing docs** (`domain.md:11`).
   - Addresses complaint 1: skills never nudge users to scaffold empty docs.
7. **Delete duplicates rather than correct them; keep one canonical block** (`.agents/install-block.md:3,53`, `writing-docs.md:19`). Handoffs and wayfinder maps reference, never copy (`handoff/SKILL.md:12`, `wayfinder/SKILL.md:23`).
   - Addresses complaints 2 and 3.
8. **Write standing text at the durability level of contracts** (types, behaviours) rather than paths and line numbers (`AGENT-BRIEF.md:9-17`).
   - Addresses complaint 3.
   - There is a tension with navigation guides, which need paths. Co-locating them with the code, as in idea 4, reduces the risk.
9. **Evidence-sized sections**: "the count stays honest to the evidence"; omit the heading when there is nothing (`writing-docs.md:54-56`).
   - Addresses complaint 2.
10. **Success signals that reward shrinking**: "`CONTEXT.md` gets shorter as often as it gets longer", and "The document gets shorter as it gets better" (`docs/engineering/domain-modeling.md:82`, `docs/productivity/writing-for-agents.md:63`).
    - Addresses complaint 2. Antmay could turn this into an actual pruning step at close; no skill here performs one.
11. **A rejected-request register, one file per concept** (`.out-of-scope/`, `triage/OUT-OF-SCOPE.md`).
    - Neutral on the complaints: it is a new doc type, but tightly gated.
    - Fits "hard to tell from code", since absent features leave no trace in the code.

**Anti-patterns and cautions:**

1. **Inline writes during conversation, gated only by prose** (`domain-modeling/SKILL.md:60-64`).
   - Produced 3,000-line glossaries "across several models" (`docs/engineering/domain-modeling.md:44,55`).
   - Worsens complaints 1 and 2.
   - Suggests Antmay's review-at-close step has real value, but the gate must be stronger than wording.
2. **Agent-authored docs that grant their own exemptions.** A wayfinder agent wrote "this map carries execution" into its own Notes and later obeyed it (`docs/engineering/wayfinder.md:69`). Also: "an unreviewed, agent-authored glossary is worse than none: it becomes confident-sounding lore" (`docs/engineering/domain-modeling.md:70`).
   - Relevant to complaint 3: wrong docs are trusted as if they were correct.
3. **Invariants kept only in `CLAUDE.md` prose, with no check.**
   - They mostly hold here through a single maintainer's discipline. They still leaked: stale `CONTEXT.md` role name, stale ADR skill and bucket names, an orphaned format file, and a hardcoded path that contradicts a documented indirection (§4).
   - Evidence that complaint 3 is not solved by rules alone, even at this small scale.
4. **Seeded docs copied into user repos with no update path**: stale "PRDs" propagated into every user repo (`CHANGELOG.md:152`), and verify mode was rejected (`.out-of-scope/setup-skill-verify-mode.md`).
   - Worsens complaint 3 for generated-then-owned files.
5. **Discarding everything but the glossary and ADRs**, which leaves "the bulk of what you agreed" in the context window only (`docs/engineering/grill-with-docs.md:39,55`).
   - This is the far extreme from Antmay's. It avoids complaint 1 but loses settled behaviour. A lean `AGENTS.md` direction should still keep some place for it; Antmay's roadmap or delta could serve.
6. **Human docs roughly 3x longer than the skills they describe** (median 1,579 vs 559 words), plus a 2,045-word page template.
