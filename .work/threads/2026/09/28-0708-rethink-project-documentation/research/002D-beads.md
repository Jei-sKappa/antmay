# gastownhall/beads — documentation research

## Summary

- **The tool keeps a user's `AGENTS.md` small by writing a pointer to a command, not to a document.** `bd init`/`bd setup` write a hash-stamped managed block (`<!-- BEGIN BEADS INTEGRATION v:1 profile:… hash:… -->`, `internal/templates/agents/render.go:77`) whose main job is to say "run `bd prime`". `bd prime` builds the full workflow context from code and live repository state, and a SessionStart hook injects it (`cmd/bd/setup/claude.go:272`). `cmd/bd/onboard.go` states the goal outright: "This keeps AGENTS.md lean while bd prime provides up-to-date workflow details." This is strong evidence for the leaning direction, with one refinement: when the context is generated by a command, it cannot drift from the code.
- **Profiles decide how much goes into the file.** The `minimal` profile (53 lines) is for agents that support hooks, since `bd prime` supplies the rest. The `full` profile (131 lines) is for agents without hooks, where the file is the only way context arrives (`render.go:16-19`, `docs/getting-started/ide-setup.md:53-55`). How lean the file can be depends on whether a runtime injection channel exists.
- **The real sync mechanisms cover a small, well-chosen set of docs.** They are:
  - a CLI reference generated from Cobra strings, pinned to a release tag, checked for drift in a way that blames only the PR that caused it, with an autofix bot;
  - a code generator driven by the OpenAPI spec, with a regeneration gate;
  - Go tests that pin specific facts in prose;
  - `Last reviewed:` markers that expire after 90 days and must name existing source paths, on 10 docs only;
  - a nav and link guard.
- **Outside those mechanisms, drift is easy to find:**
  - `engdocs/INTERNALS.md` documents a `FlushManager` and a `blocked_issues_cache` that no longer exist in code.
  - The "Noridoc" files cite Makefile and Go line numbers that have moved, and a package (`internal/rpc`) that does not exist.
  - `AGENT_INSTRUCTIONS.md` points to `ADVANCED.md` and `PLUGIN.md`, which do not exist.
  - The published plugin still ships a 337-line `/beads:template` command for a CLI command removed many releases ago.
  - The plugin skill still pins version `0.60.0`, while bd is at `1.3.0`.
- **Creating docs has almost no friction, and the result is sprawl.** The repo holds about 400 `.md` files:
  - roughly 80k words of hand-written user docs;
  - 63k words of engineering docs;
  - 34k words of agent-authored release-gate reports that nothing indexes or governs;
  - a 79k-word CHANGELOG.

  Decisions live in at least five places: `engdocs/adr/`, `engdocs/decisions/`, the plugin's `adr/`, root `PROPOSAL-*.md` files, and `--type decision` issues. `CONTRIBUTING.md:153` actively says "Update relevant .md files in the project root".
- **A human-run audit ledger decayed.** `engdocs/DOC_INVENTORY.md` sets an evidence bar and records a disposition for every doc. `engdocs/staged-for-removal/MANIFEST.md` set a deletion threshold of about 2026-09-09. At clone time (≥ 2026-09-27) all 11 staged files are still there, and the inventory still says "Keep" for the drifted `INTERNALS.md`. Only the checks bound to CI held.
- **Root `CLAUDE.md` is a model entry file:** 23 lines, all pointers. It says "Do not copy workflow… rules here; those details drift quickly when repeated across agent entrypoints", and gives a precedence rule: "If this file conflicts with a linked source, trust the linked source and fix this file by removing the duplicate." The files it points to are the opposite. `AGENTS.md` (290 lines) and `AGENT_INSTRUCTIONS.md` (531 lines) repeat each other, and `AGENTS.md` alone carries two contradictory session-close protocols.
- **Rationale is pushed into the tracker, not into docs.** 407 of 2,866 Go files under `cmd/` and `internal/` have comments citing a bead ID. The issue data lives in Dolt (`refs/dolt/data`), not in the git tree, so a clone cannot resolve any of those citations. This is the inverse of Antmay's "threads are never cited" rule, and it shows the cost.
- **The tool also sells anti-sprawl features for agent memory, but keeps them loose:**
  - `bd remember` is a key/value memory injected into every `bd prime`. Entries have no timestamps and are uncapped by default.
  - `bd rules audit` flags near-duplicate and contradictory `.claude/rules/*.md` files by Jaccard similarity.
  - Closed issues are compacted by an LLM that keeps only "Key Decisions" once they pass an age threshold.

## 2. Creation

- **Self-documentation (layer a).** Humans or agents write docs freely, and nothing gates creation.
  - `AGENT_INSTRUCTIONS.md:15` ("Update relevant .md files"), `:89`, and `:372` ("Document in README.md") tell every change to add prose.
  - `CONTRIBUTING.md:152-153` points new docs at the project root.
  - Agent rigs drop artifacts straight into the repo. The 31 `release-gates/*.md` files are signed "Evaluated … by beads/deployer" (`release-gates/be-x42v-max-rows-gate.md:10`), and no doc mentions the folder.
  - `DOC_INVENTORY.md` records that `superpowers/plans|specs` "PR-passenger planning artifact[s]" had to be removed after the fact.
  - The only prevention is `.gitignore:111-112` ("AI planning documents (ephemeral) → `history/`").
- **Friction that exists is placed after creation:**
  - the `beads-docs` skill (`.claude/skills/beads-docs/SKILL.md:217`, "commit on explicit approval");
  - the docsync guard, which requires every `docs/` page to be in navigation (`test/docsync/docsync_test.go:234`);
  - decision records marked "settled — do not relitigate without new information" (`engdocs/decisions/2026-07-10-mintlify-docs-overhaul.md:6`).
- **Generated docs** come from `bd help --docs-root` (`cmd/bd/help_all.go`) plus `tools/docsmint`, driven by `scripts/generate-cli-docs.sh`. Hand edits are rejected (see §4).
- **Layer b (user projects).** bd writes all of it:
  - `bd init` creates or updates `AGENTS.md` by default (`README.md:44`).
  - `bd setup <agent>` installs the managed block, hooks, and for Codex a skill at `.agents/skills/beads/SKILL.md` (`internal/templates/agent_skill.go`).
  - `bd onboard` prints a roughly 10-line snippet for agents that `bd setup` does not cover.
- **Work-record creation (issues)** is deliberately frictionless:
  - Required sections per issue type exist (`internal/types/types.go:808-840`; decision issues need Decision / Rationale / Alternatives Considered), but `validation.on-create` defaults to `none` (`internal/config/config.go:315`).
  - `bd prime` pushes toward creating more: "Create beads issue BEFORE writing code… Persistence you don't need beats lost context" (`cmd/bd/prime.go:784-786`).
  - The plugin's `resources/BOUNDARIES.md:372-379` warns the other way ("Mistake 4: Creating Too Many bd Issues", with a "2 week test").

## 3. Length and density

- **Entry files:**
  - `CLAUDE.md`: 23 lines, 140 words.
  - `AGENTS.md`: 290 lines, 1,683 words. About 130 of those lines are the generated managed block (160-290).
  - `AGENT_INSTRUCTIONS.md`: 531 lines, 2,641 words.
  - `engdocs/CLAUDE.md`: 93 lines. `cmd/bd/AGENTS.md`: 58 lines. `.github/copilot-instructions.md`: 138 lines.
- **Runtime context.** `bd prime` in CLI mode is "~1-2k tokens" and in MCP mode "~50 tokens" (`cmd/bd/prime.go:93-94`). The onboard text says "~80 lines". The MCP output is actually a few hundred tokens, so the 50 figure is optimistic (inference from the template at `prime.go:717-795`).
- **Docs are long and narrative:**
  - Hand-written user pages have a median of 720 words, with 8 pages over 2,400 words.
  - Active engdocs have a median of 899 words. Several single files run 4-9k words: `SERVE_RUNBOOK` 4,182, `bd-serve-v0` 5,010, `CI_CLEANUP_PLAN` 5,834, `ADDING_AN_ISSUEOPS_ROLE` 8,718.
  - ADRs run 144-239 lines and embed commit hashes and `file:line` citations (`engdocs/adr/0002-init-safety-invariants.md:9-30`).
- **Audience is marked.** The `beads-docs` skill says `docs/` is for "a user of beads — a human or agent", while `engdocs/` "may describe the implementation literally" (`SKILL.md:25-28`). Agent-facing text is identifiable by imperative capitals ("MUST", "NEVER"), bead IDs, and flag-level detail.
- **Density doctrine exists for user docs only** (`.claude/skills/beads-docs/SKILL.md:118-142`: "Most bloat is information stored in the wrong medium"). There is no equivalent for engdocs or agent files.

## 4. Sync with source of truth

Mechanisms confirmed in code or CI:

1. **Generated CLI reference.** `docs/cli-reference/*.md` carry an `AUTO-GENERATED: do not edit` banner.
   - PR CI runs `check-doc-flags` (`.github/workflows/pr.yml:405-441`), which calls `scripts/check-doc-flags.sh` and `scripts/check-doc-freshness.sh`.
   - `scripts/check-cli-docs-drift.sh` regenerates at HEAD and at the merge-base and fails only for drift the PR introduced: "contributors only own docs for the code they actually touched".
   - On failure it uploads a patch, and `.github/workflows/docs-autofix.yml` pushes that patch to same-repo PRs or comments the apply recipe on forks.
2. **Release pin.** `docs/cli-docs.pin` holds `v1.2.2`, and generation and checks build bd from that tag. The policy is in `engdocs/decisions/2026-07-17-docs-release-pin.md`: "Features that exist only on `main` are not documented". The pin is bumped at release.
3. **Spec-first wire contract.** `internal/httpapi/spec/openapi.v0.yaml` is the source, with generated types and a regeneration drift gate (`Makefile:213-235`). JSON output is pinned by a golden corpus (`cmd/bd/protocol/CATALOG.md`).
4. **Prose-fact tests** (`test/docsync/`):
   - `doltpin_test.go` fails if the Dolt version in `docs/architecture/dolt.md` prose, its install snippet, and the test container tag disagree.
   - `init_safety_recovery_test.go` requires incident-derived phrases, scoped to one section, because "two independent whole-file substring checks … stayed green through a rewrite that inverted the advice".
5. **Freshness markers.** `scripts/check-doc-freshness.sh:22-33` lists 10 docs, each with source paths. It fails when a doc lacks `Last reviewed: YYYY-MM-DD` within 90 days, lacks a `Freshness source:` line naming each source path, names a path that no longer exists, or is missing from `DOC_INVENTORY.md`. It runs on every PR. The marker proves someone re-dated the doc, not that it matches the code. `DOC_INVENTORY.md:42` admits this: "Follow-up automation should replace marker-only checks with generated or `--check` blocks".
6. **Structural guard.** `test/docsync/docsync_test.go` checks that nav entries exist, that no page is orphaned, and that link conventions and redirects resolve. It only checks Markdown link syntax, so bold-text references like `**ADVANCED.md**` (`AGENT_INSTRUCTIONS.md:529`, `engdocs/CLAUDE.md:87`) escape it.
7. **Narrow grep checks** (`check-doc-flags.sh`): removed flags and commands, plus a "pointer policy" requiring the plugin's `resources/CLI_REFERENCE.md` to stay a pointer (Check 5).
8. **Agent-file checks** in users' repos: `bd setup --check` compares the managed-block hash (`cmd/bd/setup/agents.go:220`), and `bd doctor` warns when `AGENTS.md` and `CLAUDE.md` diverge outside the managed block (`cmd/bd/doctor/legacy.go:267-367`). An opt-out marker exists, and this repo uses it (`AGENTS.md:3`).

What is not covered drifts, with concrete cases:

- `engdocs/INTERNALS.md:7-32, 184-300` describes FlushManager and `blocked_issues_cache`. Neither string exists in any `.go` or `.sql` file except the historical release notes in `cmd/bd/info.go`.
- `build-docs.md` ("Created and maintained by Nori", line 188) cites Makefile "lines 37-41" for the `install` target, which is now at `Makefile:364`. It also cites "5 build configurations", while `.goreleaser.yml` now has 7 ids.
- `cmd/bd/docs.md:15` names `@/internal/rpc`, which does not exist.
- `.github/copilot-instructions.md:16` says "Go 1.21+", while `go.mod` says 1.26.5. `CLAUDE.md:16-17` forbids hard-coding toolchain versions, but the Copilot file was not held to that.
- Plugin (layer b):
  - `commands/template.md` documents `bd template`, which was removed (`CHANGELOG.md:6308`).
  - `SKILL.md:10` says `version: "0.60.0"`, and `SKILL.md:110` says the skill "may be stale" if bd is newer, which is now always true. `scripts/check-versions.sh` checks the plugin.json files but not `SKILL.md`.
- **Expiry and archival.** There is a staged-for-removal process with rescue criteria (`MANIFEST.md`). The deletion threshold passed without anyone acting on it.

## 5. Agent-facing files

- **Division of responsibility (layer a):**
  - `CLAUDE.md` is only pointers plus four ground rules, with a rule to delete duplicates.
  - `AGENTS.md` claims to exist "for compatibility" and to defer to `AGENT_INSTRUCTIONS.md` (lines 5-7). It then restates bd-edit warnings, a non-interactive shell rule, and a full "Landing the Plane".
  - `AGENT_INSTRUCTIONS.md:180-184` points back to `AGENTS.md` as canonical for session completion, so the pointers are circular.
  - `engdocs/CLAUDE.md` holds the "architecture orientation", but says "See AGENTS.md 'Adding a New Command'" (line 93), and that section is actually in `AGENT_INSTRUCTIONS.md:365`.
  - The "bd edit" warning appears in `AGENTS.md`, `AGENT_INSTRUCTIONS.md`, `cmd/bd/AGENTS.md`, the Codex skill template, and `bd prime`.
- **A contradiction inside one file.** `AGENTS.md:150-154` says "NEVER stop before pushing … YOU must push". The managed block at `AGENTS.md:261` says "Conservative (default): Do not run git commits, git pushes… unless explicitly asked". The block does declare itself subordinate to repository instructions (`:267`), which resolves the conflict on paper but leaves it for the agent to work out.
- **Rules enforced in code alongside prose.** `.claude/settings.json` wires `PreToolUse` hooks. `.claude/hooks/block-interactive-cmds.sh` denies `cp`/`mv`/`rm` without `-f`. The same rule is still written out in `AGENTS.md:96-118`.
- **Orphans.** Nothing references `.claude/test-strategy.md` or `.agent/workflows/resolve-beads-conflict.md`.
- **Progressive disclosure in layer b:**
  - The managed block points to `bd prime`.
  - `bd prime` varies its output by state: git remote, ephemeral branch, stealth mode, and `agent.profile` (`prime.go:797-960`).
  - `bd prime` starts with a truncation directive ("If this output is truncated … read the full persisted hook output", `prime.go:471`).
  - Customization is layered: `.beads/PRIME.md`, then the redirected beads dir, then `~/.config/beads/PRIME.md` (`prime.go:239-260`).
  - Memories can be capped with `--max-memories` / `--max-memory-chars`, and an elision banner reports what was dropped.
  - The plugin skill applies the same idea. `plugins/beads/skills/beads/adr/0001-bd-prime-as-source-of-truth.md` records cutting `SKILL.md` "from 3,306 to ~500 words" and pointing CLI detail at `bd prime` / `--help` ("~3,000+ tokens loaded even for simple operations"). The 15 resources behind the skill still total thousands of lines (`DEPENDENCIES.md` alone is 747).
  - Help supplements are Markdown compiled into `--help` (`cmd/bd/help_supplements.go:14`).
  - `bd info --whats-new` and `bd upgrade review` print "agent-actionable" release notes on demand (`cmd/bd/info.go:228`).
  - The MCP server lazy-loads tool schemas (`integrations/beads-mcp/CONTEXT_ENGINEERING.md`, "~10-50k" down to "~2-5k tokens").
- **Contradiction across layer-b surfaces.** `bd prime` says "Prohibited: Do NOT use TodoWrite" (`prime.go:783`), while the plugin's `BOUNDARIES.md:28` says "TodoWrite is fine" for single-session work.

- **Decisions have five homes:**
  - numbered ADRs, with context full of commit-hash archaeology (`engdocs/adr/0002…:13-30`);
  - dated decision records naming the decider, with "Recorded, not fixed" follow-ups (`engdocs/decisions/2026-07-10…:89-94`);
  - the plugin's `adr/`;
  - root `PROPOSAL-*.md`, some marked "Historical — … superseded" but left at root;

- **Navigation guides:**
  - `engdocs/ADDING_AN_ISSUEOPS_ROLE.md` is a real "what a change costs, file by file" guide, but runs 880 lines.
  - `engdocs/CLAUDE.md` gives a layer-to-package map.
  - `AGENT_INSTRUCTIONS.md:17-28` has a stale 7-line tree, and its storage steps (`:374-381`) do not reflect the issueops role rule.
- **Invariants live in tests and help text.** docsync tests encode incident lessons in their doc comments. Makefile comments explain why gates are shaped the way they are.
- **Rationale by citation.** Code comments cite bead IDs and GH issues: 889 comment lines across 407 Go files for bead IDs, 1,331 comment matches for `GH#`. The standing explanation is "go read the issue". For bead IDs, that issue lives in a Dolt database this clone does not contain, and some IDs belong to other organizations' trackers (`wy-`, `ga-` prefixes, e.g. `PROPOSAL-cas-conditional-update.md:4-6`).

## 7. Work records

- **The tracker is the record.**
  - Issues carry `description`, `design`, `acceptance`, and `notes` fields, plus `discovered-from` links. Execution metadata keys (`execution_agent_type`, `execution_suggested_model`, …) are "authoritative execution hints" (`AGENT_INSTRUCTIONS.md:197-217`).
  - Data lives in Dolt, and sync goes over `refs/dolt/data`. CI blocks PRs that touch `.beads/issues.jsonl` (`pr.yml:529-552`).
  - Workflows are formulas: TOML templates poured into issue graphs (`.beads/formulas/beads-release.formula.toml`).
  - Markdown plans can be converted into issues (`integrations/claude-code/commands/plan-to-beads.md`, `bd create --graph plan.json` in `cmd/bd/help_supplements/create_graph_plan.md`).
- **The argument for a database over Markdown** is short in-repo:
  - `README.md:15`: "replaces messy markdown plans with a dependency-aware graph".
  - `docs/core-concepts/index.md:6-11`: "Markdown plans rot, TODO comments scatter, and a crashed agent takes its context with it."
  - The plugin's `BOUNDARIES.md`: "markdown swamps", plus the "2 week test".
  - The long-form case is in off-repo articles listed in `ARTICLES.md`.
- **Decay.** Closed issues past a day threshold are summarized by Haiku into Summary / Key Decisions / Resolution. The summary must be shorter, otherwise compaction is skipped (`internal/compact/haiku.go:268-296`, `internal/storage/issueops/compaction.go:40-80`). Tier 2 requires tier 1 first. `bd compact` squashes old Dolt commits.
- **Memory.** `bd remember "…"` stores a key/value memory that every `bd prime` injects. The rendering comment says the store "keeps no timestamps, so alphabetical is the only stable order" (`prime.go:583-584`). Caps are off by default. Agents are told "Do NOT use MEMORY.md files" (`prime.go:785`, `internal/templates/agents/defaults/beads-section-minimal.md:18`).
- **Session hand-off.** "Landing the plane" files follow-up issues and produces a next-session prompt (`AGENTS.md:120-158`).
- **Other work records committed as files:**
  - `release-gates/*.md`: 31 files, unindexed, and they cross-reference each other ("see memory `deployer-worktree-stray-rebase-lib-copy`", `release-gates/be-a8g61…:42`);
  - the CHANGELOG, hand-written in Keep a Changelog format with paragraph-length entries;
  - `versionChanges` in `cmd/bd/info.go`.
- **Feedback into standing docs** is manual only. Staged docs carry "Convert still-relevant findings into active docs or beads issues" (`MANIFEST.md:20`). Decision records list follow-ups. `CONTRIBUTING.md:158-166` embeds a code convention that cites "designer §4 of be-x42v". Nothing lands tracker content into docs.

## 8. Ideas to borrow and anti-patterns

**Borrow:**

1. **Managed block plus a context command** (`internal/templates/agents/render.go`, `cmd/bd/prime.go`, `cmd/bd/onboard.go`).
   - Complaints addressed: 2 (lean entry file) and 3 (context generated from code and state, so it cannot drift).
   - Bearing on the leaning direction: strong support. Antmay could keep an `AGENTS.md` block pointing to a "print what applies now" step. That could be a skill, or a script that lists records and descriptions by frontmatter; `consult-decisions` already does something similar.
2. **Hash-stamped managed sections with a check** (`agents.go:220`, `doctor/legacy.go:267`).
   - Complaint addressed: 3, for method-owned text inside a user's `AGENTS.md`/`CLAUDE.md`.
   - Bearing on the leaning direction: it lets Antmay own a region of `AGENTS.md` without taking ownership of the whole file.
3. **Profiles by delivery channel** (`ide-setup.md:53-55`).
   - Complaint addressed: 2.
   - Bearing on the leaning direction: a refinement. How lean the file can be depends on whether the agent has a load-on-demand path.
4. **Entry-file precedence rule** (`CLAUDE.md:3-4, 22-23`).
   - Complaints addressed: 2 and 3.
   - Bearing on the leaning direction: support. Antmay could adopt the rule "entry file holds pointers; on conflict trust the target and delete the duplicate".
5. **Generated reference pinned to a release, with blame-scoped drift checks and autofix** (`scripts/check-cli-docs-drift.sh`, `docs-autofix.yml`, `docs/cli-docs.pin`).
   - Complaint addressed: 3.
   - Bearing on the leaning direction: support. Anything the code can emit should be emitted, not written. The analogue for Antmay is generating skill-list tables from `SKILL.md` frontmatter.
6. **Prose-fact tests** (`test/docsync/doltpin_test.go`, `init_safety_recovery_test.go`).
   - Complaint addressed: 3, for the few claims that matter most.
   - Bearing on the leaning direction: `close-thread` could land a delta together with a pinned assertion. This is cheap, targeted, and fails loudly.
7. **Freshness markers that must name existing source paths** (`scripts/check-doc-freshness.sh`).
   - Complaint addressed: 3, partially. The path-exists check is objective; the date bump can be gamed.
   - Bearing on the leaning direction: a lighter option would require each description to name its source files and fail `close-thread` when those paths vanish.
8. **Pointer-policy check** (`check-doc-flags.sh` Check 5, plugin `resources/CLI_REFERENCE.md`).
   - Complaints addressed: 1 and 3.
   - Bearing on the leaning direction: support. Assert that a file stays a pointer and has not grown back into a copy.
9. **Evidence bar and disposition ledger with a quarantine** (`engdocs/DOC_INVENTORY.md:10-13`, `staged-for-removal/MANIFEST.md`).
   - Complaint addressed: 1. The "rescue only verified paragraphs, never restore wholesale" rule is especially good.
   - Caveat: it decayed because nothing enforced it. It is only worth borrowing if a skill or check runs it.
10. **Loss-check plus adversarial fact-check for trimming** (`.claude/skills/beads-docs/references/simplification.md`).
    - Complaint addressed: 2, without losing facts. "Word count is the output, not the target."
11. **Rule-sprawl audit** (`cmd/bd/rules.go`, `engdocs/RULES_AUDIT_DESIGN.md`).
    - Complaints addressed: 1 and 2 for agent rules. Its motivating example: 40 rule files costing about 12k tokens per session.
    - Bearing on the leaning direction: a lexical check for near-duplicate or contradictory bullets across `AGENTS.md` and records would have caught this repo's own contradictions.
12. **Required sections per record type, with decision records needing Alternatives Considered** (`internal/types/types.go:825-829`).
    - This mirrors Antmay's "Rejected alternatives". Beads defaults validation to `none`, which is a warning about what happens when the gate is optional.

**Anti-patterns:**

1. **Circular and duplicated entry files** (`AGENTS.md` ↔ `AGENT_INSTRUCTIONS.md` ↔ `engdocs/CLAUDE.md`, contradictory push rules).
   - Complaints worsened: 2 and 3.
   - Lesson: one file must own each rule. A "compatibility" file that restates content drifts.
2. **"Update relevant .md files" as a blanket rule** (`CONTRIBUTING.md:152-153`, `AGENT_INSTRUCTIONS.md:15`).
   - Complaint worsened: 1. It argues for Antmay's stance that a doc needs a reason to exist.
3. **Agent-authored reports committed as permanent files with no owner** (`release-gates/`, root `PROPOSAL-*.md`, `VERSIONED-BEADS-WRITE-PATHS.md`).
   - Complaints worsened: 1 and 3.
