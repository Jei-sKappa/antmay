2. Create `suite/shared/references/formats/delta-document.md`. Paragraph: a delta document is one file in a thread's `delta/`, naming one project-layer file as its target by mirroring the target's path under `delta/` and carrying one of three types; the thread's delta is the whole folder, authoritative inside the thread from the moment written and landed only at close. `## Shape`: three fenced skeletons — `create` (frontmatter `type: create`, body is the whole new file), `edit` (the spec's reference body verbatim: frontmatter `type: edit` and `hash: <git blob hash>`, then `## add` with an anchor line and a fenced text block, `## replace` with two fenced blocks, `## remove` with one fenced block), `delete` (frontmatter `type: delete` and `hash`, nothing else). Use four-backtick outer fences so the inner three-backtick fences render. `## Rules`: one delta document per target per thread, its path under `delta/` mirrors the target's path so the target is the path; the frontmatter carries `type` and, for `edit` and `delete`, `hash`, and nothing else; `hash` is the git blob hash of the target as it stood when the document was drafted, `git hash-object <target>` on the working tree, re-recorded when the document is amended after the target changed; every operation carries literal text and an instruction-style operation is not an operation; `add` carries the text and one anchor — `under:` the exact heading it goes under, `after:` the exact line it follows, or `end`; `replace` carries the exact existing text then the new text; `remove` carries the exact existing text; exact means exact after normalising line ends and trailing spaces; a `create` targets a file that does not exist and its body for `docs/adr/` or `docs/pdr/` is the decision-record format, with the stem assigned when the document is first written and never changed; a `create` for `docs/glossary.md`, `docs/product/<capability>.md` or `docs/architecture/<module>.md` is the whole file in that kind's format.
3. Create `suite/shared/references/formats/change-document.md`. Paragraph: `change.md` at the thread root is the **change document**, the thread's design of one change, written once the discussion has settled, amended in place afterwards, historical once the thread closes, and cited from every downstream artifact; it holds only what is thread-only. `## Shape`: a fenced skeleton with a title and headings of the author's choosing that cover, in this order or another, the goal, the context, scope and non-scope, constraints, the change (what the deltas add, replace and remove, cited by delta document path, plus any one-off work), acceptance (a flat list of behavior statements, one `- ` bullet per line), degrees of freedom, inferences, and a delta index (every delta document by path with its type). `## Rules`: the one rule — a sentence that describes standing behavior of the product or standing structure of the system is written in a delta document and cited from the change document, never written in its body; acceptance is a flat checklist covering everything the implementer builds including what is obvious from the code, carries no `FR-`, `AC-` or other identifier or numbering, and is referenced downstream — by a plan task, a report row or a review finding — by quoting a criterion verbatim; the delta index lists every delta document of the thread by path with its type; within-thread references are thread-relative (`log.md`, `delta/docs/adr/<stem>.md`) and project-level references repo-relative; an amendment keeps the superseded text, marked with the date and the reason, and a delta document is amended together with the change that affects it; the file carries no frontmatter; and the routing table, headed `### Routing` inside `## Rules` or as its own bullet introducing the table, reproduced from the spec's `### Routing` with the same eight rows and four columns (a settled sentence that… / goes to / drafted by / lands), with "the change authoring" written as the drafter and "close" as the landing.
