### Task 1: Decision-record and description formats

**Objective:** Give the project layer's kinds their shared formats — one decision-record format covering ADR and PDR, one format each for product behavior and architecture description — and narrow the glossary format to the project glossary alone.

**Input / context:** `spec.md` `## The project layer` (the kinds table, `### Admission rules for descriptions`, `### Decision records`), `## Degrees of freedom` (one format file for ADR and PDR is the plan's choice here; the heading scheme inside a description is fixed as title, `##` per area, one statement per bullet), `## Inferences` (folder is kind; no frontmatter kind or status field; a record whose kind changes is a `delete` plus a `create` in the new home). The thread's `glossary.md` rows **ADR**, **product decision record (PDR)**, **product behavior**, **architecture description**, **description**, **decision test**. The format skeleton in `suite/authoring/shared-references.md`: title `# <Artifact> format`, one paragraph, `## Shape`, `## Rules`, nothing else. Current files: `suite/shared/references/formats/adr.md` (replaced), `suite/shared/references/formats/glossary.md` (edited). This task starts from the baseline commit; no earlier task.

**Steps:**

1. Create `suite/shared/references/formats/decision-record.md` following the format skeleton. The paragraph states: a decision record holds one project decision in one file `<yymmddhhmm>-<slug>.md` (stamp in UTC at minute resolution, kebab-case slug, the stem is the record's global identifier); an **ADR** at `docs/adr/` records how the system is structured or built, a **PDR** at `docs/pdr/` records what the product does or for whom; each folder has its own `superseded/`; a record is filed by the question it answers, never by how it is enforced; location carries the state (current in the folder, superseded or retired in `superseded/`); a record is drafted in a thread as a `create` delta document at `delta/docs/adr/<stem>.md` or `delta/docs/pdr/<stem>.md` and lands at close.
2. Write its `## Shape`: frontmatter `name` (the decision as a full sentence), `description` (one sentence for the catalog), optional `supersedes` (list of stems); a body giving the context, the decision and the reason; a `## Rejected alternatives` section with one line per alternative and the reason it lost; an optional `## Consequences` section.
3. Write its `## Rules`, one bullet each: `name` and `description` always present; `supersedes` omitted when the record replaces nothing, and every stem it names lives in the same folder as the record (a record whose kind changes is a `delete` delta plus a `create` delta in the other folder); `## Rejected alternatives` is mandatory because a record with no alternative records no choice; `## Consequences` is optional and holds the revisit condition of a deferral when the discussion argued one; the **decision test** — a settled point becomes a record only when all three hold: (1) a real alternative was argued against and is named with the reason it lost, (2) the reason for the choice cannot be read off the code, the product behavior or the architecture description, (3) a later thread could build against it incorrectly if not told; a mixed point is split and its structural half becomes an ADR only if it passes the test alone; the body states the choice in the present tense and carries no implementation state and no version in name, stem or body, because whether the choice is built is read from the code and the roadmap and whether it is current is read from the folder; the record is concise and limited to what a new reader needs; the file carries no status, lifecycle or kind key, since the folder is the kind and the location is the state; the stem is assigned when the delta document is first written and never changes; landing a record that names `supersedes` moves each named record into that folder's `superseded/` with its content untouched; one short note that editing or deleting a landed record is generally poor practice, with no prohibition.
4. Remove `suite/shared/references/formats/adr.md` with `git rm`.
5. Create `suite/shared/references/formats/product-behavior.md` following the skeleton. Paragraph: one document per **capability** at `docs/product/<capability>.md` holding present-tense statements of what the product does now, FR and NFR alike; part of the project layer; living, changed only through delta documents landed at close; cited by path and heading. `## Shape`: a fenced skeleton with `# <Capability>`, `## <area>` headings, and `- <statement>` bullets beneath each. `## Rules`: a statement enters only when the behavior is built and only when reading the code would not make it obvious, and the document never describes behavior that does not exist; one statement per bullet, present tense, concise; a statement may carry a one-clause reason when no decision record holds it; behavior settled but not built has exactly one home, the roadmap entry that will build it; the file name is the capability's kebab-case slug; the file carries no frontmatter and no status, lifecycle or kind field.
6. Create `suite/shared/references/formats/architecture-description.md` the same way for one **module** at `docs/architecture/<module>.md`: how the system is structured now, admitted only where no single file makes it obvious, never describing structure that does not exist; same shape (`# <Module>`, `## <area>`, `- <statement>`), same rules adapted to structure.
7. Edit `suite/shared/references/formats/glossary.md`: the paragraph describes only the project glossary at `docs/glossary.md`, the naming authority fixing one meaning per term; `## Shape` unchanged; `## Rules` keeps the one-row-one-meaning rule and the `##` sections rule, and replaces the thread-glossary rules with: the glossary changes only through a thread's delta documents landed at close; a term leaves the vocabulary through a `remove` or `replace` operation on its row; a row may reserve a word by stating which sense is reserved and what to write instead.
8. In `suite/shared/manifest.yaml`, replace every `formats/adr.md` entry with `formats/decision-record.md` (under `skills/close/close-thread`, `skills/capture-discussion/discussion`, `skills/capture-discussion/resolve-pending-decisions`, `skills/model-invoked/consult-adrs`).
9. In the four bodies that point at it — `suite/skills/close/close-thread/SKILL.md`, `suite/skills/capture-discussion/discussion/SKILL.md`, `suite/skills/capture-discussion/resolve-pending-decisions/SKILL.md`, `suite/skills/model-invoked/consult-adrs/SKILL.md` — replace the pointer `<skill_path>/references/formats/adr.md` with `<skill_path>/references/formats/decision-record.md`, changing nothing else (their roles are rewritten in later tasks).
10. Delete the four orphaned mirrored copies `suite/skills/*/*/references/formats/adr.md` by hand.
11. From `suite/`, run `node scripts/sync-shared-references.mjs`, then `node scripts/check-marketplace-skills.mjs` and `node scripts/check-skill-text.mjs`.
