### Task 4: Add apply-delta and distribute the scripts

**Objective:** Add `apply-delta.mjs`, which lands a whole delta or writes nothing. Then ship both scripts to the skills that run them, with `check-delta.mjs` going to `spec`, `review-spec` and `close-thread`, and `apply-delta.mjs` going to `close-thread` alone. Finally, document scripts as a kind of shared reference.

**Input / context:**
- This task starts from Tasks 2–3's `suite/shared/references/scripts/check-delta.mjs` and its exports.
- Requirements: `spec.md`, `### The scripts` (the `apply-delta.mjs` part and **Manifest.**), and `### Formats and authoring convention` (the `suite/authoring/shared-references.md` bullets).
- Why only `close-thread` holds `apply-delta.mjs`: `delta/docs/adr/2610021413-delta-landed-by-shipped-scripts.md`.
- `apply-delta.mjs` lands documents and does nothing else. The supersede move and every other closing write stay with `close-thread`'s body.
- `suite/scripts/sync-shared-references.mjs` copies any declared file byte for byte, so it mirrors `.mjs` files unchanged. `suite/scripts/check-skill-text.mjs` walks only `.md` files.
- The glossary's **shared reference** row and `suite/AGENTS.md`'s layout tree change through this thread's delta (`delta/docs/glossary.md`, `delta/suite/AGENTS.md`). Edit neither by hand.
- Documentation rule (Global Constraints): describe scripts as a kind that has always been there, with no before/after wording.

**Steps:**
1. Create `suite/shared/references/scripts/apply-delta.mjs`, with a `#!/usr/bin/env node` line and a header comment in the style of `check-delta.mjs`. The comment states that it lands a thread's delta all or nothing, that it imports `./check-delta.mjs`, that it uses only `node:` built-ins, and its exit codes.
2. Import `checkDelta` and `formatReport` from `./check-delta.mjs` by that relative specifier. Import nothing else outside `node:` built-ins.
3. Implement `node apply-delta.mjs <thread root>`, with the project root taken as the current working directory:
   - When the argument is missing or the thread root is not a directory, exit 2 with a usage message.
   - Run `checkDelta(threadRoot)`.
   - When the result has any failure, print `formatReport(result)`, write nothing, and exit 1.
   - Otherwise land, in this order:
     - every `create` writes its `landed` content to the target, creating parent folders with `mkdirSync(…, { recursive: true })`;
     - every `edit` writes its `landed` content to the target;
     - every `delete` removes the target with `rmSync`.
   - Write exactly the computed `landed` strings, so the check predicts the landing.
   - Print one line per file, `wrote <target>` or `removed <target>`, and exit 0. A delta with no documents prints `no delta documents` and exits 0.
4. Use the same direct-run guard as `check-delta.mjs`: `import.meta.url === pathToFileURL(realpathSync(process.argv[1])).href`.
5. In `suite/shared/manifest.yaml`:
   - add `  - scripts/check-delta.mjs` to the lists of `skills/spec/spec`, `skills/review/review-spec` and `skills/close/close-thread`;
   - add `  - scripts/apply-delta.mjs` to `skills/close/close-thread` only.
6. From `suite/`, run `node scripts/sync-shared-references.mjs`.
7. Edit `suite/authoring/shared-references.md`, `## The canonical folder`:
   - Reword the opening "passive material" sentence so that it covers scripts. Example: a file earns a place there when it is canonical material, passive text or a script a skill runs, that more than one skill must reproduce identically.
   - Change "Three kinds live there." to four kinds.
   - Add a **Scripts** (`scripts/`) paragraph after the instructions paragraph:
     - a script is dependency-free Node that uses only `node:` built-ins, because a skill folder cannot carry `node_modules`;
     - it is mirrored byte for byte like every other shared reference, and is run from a body through its `<skill_path>/references/scripts/` path;
     - a script that imports another by relative path is declared together with it for every skill that runs it.
8. In the same file, `## The manifest`, extend "A skill declares every shared file it reads or writes through" to cover the scripts a skill runs.
